# 问题清单

本文件是本项目**长期问题清单的唯一真源**，由 `work-queue-stack` 的 `survey` 命令只读抽索引。
解析契约：表格中**以 `| ISS-<数字> |` 开头的行**会被当成真实待办列出（解析器不识别代码围栏，写在代码块里同样会被解析）。
因此示例与占位一律写成 `ISS-0xx` / `ISS-xxx`（不含纯数字形式），或不要以竖线开头。

## 约定

- **状态**：`open`（待处理）、`planned`（已排期）、`in_progress`（处理中）、`resolved`（已解决）、`wontfix`（评估后不做，须写理由）。
- **优先级**：`P0` 阻塞主线；`P1` 影响结论可信度或可比性；`P2` 治理/工具/环境，不阻塞业务但会累积风险。
- **类型**：`数据/输入`、`实现`、`验收/证据`、`环境/资源`、`流程/范围`（沿用 `explain-task-failure` 的失败分类）。
- 每条必须给出**可核验的完成标准**；无法验证的写法（如「质量提升」）不得作为完成标准。
- 解决后不删除条目，移入「已解决」区并写解决方式与证据路径，保留可追溯性。
