# 最小任务输入与交接约定

整理上下文、检查执行前输入或跨 Skill/角色交接时读。本文件定义共享信息语义，
不定义执行状态机，不授予实施权限，也不要求每次调用 `project-context-brief`。
角色字段和评审格式仍由 `single-phase-execution-loop/references/role-contract.md` 定义。

## 输入：只补当前一步需要的内容

| 信息 | 应能回答的问题 |
| --- | --- |
| 目标与成功判据 | 当前一步要解决什么，什么观察或证据意味着完成？ |
| 范围与非目标 | 可修改、可实验或可分析什么，哪些明确不做？ |
| 事实与来源 | 已知事实依据在哪里，哪些只是推断，来源是否仍适用？ |
| 质量要求与风险边界 | 当前用途需要什么质量，哪些风险不能接受，哪些能力明确暂缓？ |
| 当前未知与决策 | 缺口是可查事实、待验证知识还是用户取舍，是否阻塞下一步？ |
| 当前行动与权限 | 下一步是什么，由谁处理，原授权允许做到哪里？ |

这六项是信息检查，不是六个必填字段或新文件。已有请求、计划、约束、测试和报告能回答时直接复用；
简单任务可以只用几句话。不让用户重填已知信息，也不为了模板完整扫描全仓库。
交给另一个角色时，提供当前一步所需的事实与约束摘要，并附可读取的来源位置；不能只丢一个无权限访问的链接。
有阶段/版本绑定时沿用原标识；没有时用准确任务描述定位，不为格式完整虚构 campaign、Phase 或帧。

就绪只针对具体下一步：无关未知可以保留，但影响该步正确性、验收或授权的关键缺口须先处理。
现有事实先定向查；技术知识缺口交回调用者判断是否探索；价值取舍给用户选项和影响。
缺口不阻塞的已授权工作可继续，不把“还有未知”一律转成全任务 blocked。

## 质量：按任务用途决定，不按熟悉度推定

在已确认用途、质量要求和风险边界内选择合适实现，既不擅自降低标准，也不追加工程目标。
熟悉程度决定缺什么知识，不决定交付质量；陌生项目可能要求生产质量，熟悉项目也可能只做一次性实验。

- 从适用项目指令、用户请求和批准计划提取要求，保留来源；上下文摘要不覆盖它们。
- 区分必须满足的要求、明确暂缓的能力和可选建议。没有提到某能力，不等于已批准放弃必要保障；
  也不能将“以后可能需要”升级为本阶段必须完成。
- 未明确质量等级时沿用已有项目约束及本次成功判据，不默认生产级或原型级；
  只有缺口会实质改变当前方案、风险或验收时才向用户确认。
- 生产任务保留已要求的兼容、稳定、维护与扩展约束；原型也保留最小可用验证、授权及适用的数据、安全边界。
- 项目硬约束与任务诉求冲突时指出来源和影响，等待澄清；不得借“只要可用”静默绕过。
- 当前任务的质量变更由有权决定者确认，沿原计划维护流程记录；受控快照必须走原版本与批准流程。
  不从上下文包、探索结论或角色报告中偷改验收。

Designer 说明设计为何匹配这些要求；Executor 不顺手扩展功能；Reviewer 对照同一要求和实际证据判断。
FAIL 应指出违反的目标/约束、影响及证据；纯可选的未来改进不构成 FAIL，
但必要风险和关键未验证项也不能因“原型”被忽略。
只影响未来的建议保留为建议，不强制创建任务、开栈或追加阶段。

## 交接：能找回原任务，能判断下一步

在既有输出中表达以下信息，可合并句子或引用已有记录，不新增必填报告：

```text
返回位置：原任务 / 阶段 / 帧（若存在）及接收者
本次结论：补齐、支持或推翻了什么，解锁哪一步
证据来源：来源位置与适用范围；事实、推断和未验证部分分开
剩余缺口：哪些还未知或受阻，是否影响当前下一步
下一步：谁做什么；原授权可继续，或需何种批准/外部条件
```

来源范围按任务需要注明，如分支/版本、样本、环境或约束；小样本实验不能直接证明全量效果。
对原记录只补变化部分；任务栈仅存位置和指针，阶段状态仍归原进度文件/台账，不创建交接状态真源。

接收方核对返回位置、来源适用性、阻塞是否解除和继续权限后，回到具体执行步骤。
材料已过时或与新证据冲突时只核对受影响部分；新证据推翻旧路由才重新诊断，不把所有 Skill 再跑一遍。
推翻设计时回设计入口；受控方案变更回用户审批；只问分析的请求到建议为止。
缺少角色/下游能力时交回原调用者，不擅自委托、改用另一流程或假称已执行。

三条不能混淆：**输入充分 ≠ 执行授权；探索得到答案 ≠ 实现完成；Reviewer PASS ≠ 受控阶段获用户批准。**
