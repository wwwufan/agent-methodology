# 探索帧记录协议

需要把探索挂入 `campaign-work-stack`、做跨窗口交接或形成可复盘证据时读本文件。

## 一帧一个知识问题

探索帧按“需要回答的问题”划分，不按命令、代码文件或每次试验划分。
同一问题在预算内且未触发停止条件时可运行多个实验；只有问题本身变了，才新建探索帧。
预算连续性与无进展判据见 [budget-and-progress.md](budget-and-progress.md)。
重开已关闭问题也需引用历史消耗，不能把新帧当新额度；记录仍放在原实验报告，栈只保留指针。

## 映射到现有栈字段

| 栈字段 | 探索语义 |
| --- | --- |
| `title` | 要回答的具体问题 |
| `goal` | 这个问题将解锁的技术决策 |
| `criteria` | 假设、最小实验、预先判据、证据和路由结论均已形成 |
| `origin` | 引发探索的 capture、Reviewer FAIL 或任务请求 |
| `pointers` | 样本、脚本、日志、指标、报告或 issue 的可反查位置 |
| `close_note` | 预算、假设、实验、实际结果、结论和返回路由 |

当前 schema 不需要增加全局 `exploration_mode`。探索是帧级语义，由标题、目标、判据与收口结论表达。

## 压帧模板

```text
title:
  验证 <具体未知>

goal:
  获得足以决定 <待解锁决策> 的证据

criteria:
  - 知识问题与候选假设已明确
  - 最小区分实验、预期观察和探索预算已预先记录
  - 实际结果与可反查证据已记录
  - 已形成返回 Executor、Designer、用户或终态的结论

origin:
  认知缺口 <capture-id / review-id / 用户请求>；返回 <原任务/阶段/父帧与接收者>
```

有活动栈且问题阻塞当前帧时：

1. `capture --found-in <父帧> --disposition blocks`；
2. `push --parent <父帧> --activate` 建立探索子帧；
3. `resolve --capture <C-id> --disposition blocks --frame <子帧>`；
4. 子帧收口时用 `pop`，父帧由栈自动恢复。

## 实验记录模板

```text
问题：
<现在不知道什么？>

解锁的决策：
<得到答案后能决定什么？>

预算：
<计量方式、累计已用 / 上限、历史记录位置；剩余量与停止条件>

候选假设：
- H1: ...
- H2: ...

最小区分实验：
<如何以最小成本区分 H1/H2？>

预先判据：
- 若观察到 ...，支持 H1
- 若观察到 ...，支持 H2
- 若观察到 ...，本实验无法区分

实际结果：
<数据与异常，不先写解释>

有效进展：
<本轮新增证据或减少的阻塞；有效 / 无效及依据；连续无进展轮数>

证据指针：
<命令、日志、样本、报告或文件路径，以及结论适用的样本/环境/版本范围>

结论：
<支持 / 推翻 / 无法区分哪些假设？>

路由：
<返回的原任务/阶段/帧（若有）与接收者；解锁的下一步、剩余阻塞及继续权限>
```

## `close_note` 模板

```text
预算：<同一问题累计已用 / 上限及历史指针>
假设：<H1, H2>
实验：<最小区分实验>
结果：<实际观察>
证据：<可反查指针及适用范围>
结论：<支持、推翻或无法区分>
进展：<本轮有效进展与依据、连续无进展轮数、是否触发暂停>
路由：<原任务位置、返回对象、下一步、剩余缺口及继续权限>
```

`done` 必须同时有结论与路由。预算耗尽却仍无法决策时用 `parked`，不得用模糊的 `done` 伪装收敛。
无进展暂停时保留未关闭探索帧及报告指针，不自动关闭或激活父帧；若按明确处置决定搁置，
用 `parked` 并写恢复条件。父帧即使因出栈恢复，也必须先核对知识阻塞和预算，不能自动开始实施。

## 证据存放

- 小型结果可直接写入 `close_note`；
- 大型日志、样本、指标或报告放入项目合适的证据位置，栈里只留 `pointers`；
- 稳定的技术结论进项目文档或 issue，不在栈 JSON 中复制长文；
- 不创建与既有文档、issue 或台账重复的平行真源。
