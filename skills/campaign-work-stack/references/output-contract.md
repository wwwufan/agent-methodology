# 完整记录与分级展示

组织阶段汇报、失败解释或任务栈摘要时读；读取本文件不启用任务栈或编排。
只调整面向用户的展示，不改变执行、记录、状态真源、校验或批准门禁。

## 三种展示

| 场景 | 面向用户的必要信息 |
| --- | --- |
| 正常推进 / 仍可继续的失败 | 当前结论、关键变化、下一步；失败时说明原因、未通过部分及剩余重试/预算 |
| 用户决策 / 预算耗尽 / 无进展暂停 / 阻塞 | 已确认事实与未知、影响、证据、停止原因、选项与推荐、准确恢复条件 |
| 阶段交付 / 中断恢复 / 查询全局 | 完成与未完成、验证证据、风险、当前任务位置、剩余待办及下一步权限 |

不强制逐项标题；信息可合并为短段或列表。用户要求详细时展开，
但不能用简报隐藏 blocker、高风险、待批准事项、重要未验证项或失败状态。
受控流程仍须显示阶段/版本、实际 Goal 绑定、最近门禁、下一步由谁执行和准确指令。

## 完整性不变

- 角色报告、Reviewer YAML、验证证据、预算与纠正历史仍完整保存；摘要附可追溯位置。
- 内外层复用同一报告，只补新变化。摘要不改变状态，不覆盖真实失败，不替代验收或用户批准。
- 栈脚本原有输出不删减。主代理读取完整结果后再摘要，不能为减少展示跳过 show、verify、pop 或 retro。
- 恢复任务、切换 campaign 或用户查询全局时，原样展示完整推进树与位置指针；
  同轮普通 push/activate/pop 后可只报位置变化与待办，不反复粘贴整棵树。
- pop 回看仍覆盖结论、衍生去向、剩余任务、下一步四类信息，可合并展示并链接完整记录；
  非阻塞衍生可按去向汇总，阻塞/高风险及待用户决定的事项不得折叠掉。
- retro 仍运行；有新增放弃、搁置或改道时说明原因、影响和去向。
  无新增变化可简报并保留完整复盘入口；用户要求完整复盘时展开。
  区分脚本的“activated/切换”事件与真正方案改道，不把正常阶段切换解释成返工。

## 失败解释

事实、推断与未验证项必须分开；已知根因就直说，未知根因不要硬填。
术语首次出现且会妨碍理解时解释；日常类比仅在有助理解因果或用户要求时提供，不强制凑例子。
同一次失败由负责方解释一次，其他层复用。已有证据与下一步明确时不再完整诊断。
